Fork of Inco's Splash 109Metal · C++ · Apple7/8 GPUs

Splash for M1 and M2

Upstream Splash needs an M3 or newer. Its kernels use bfloat16, which the M1 has no hardware for, and Apple's MPP matrix library, which reaches about a third of the GPU's peak there. I rewrote those parts to use formats the M1 runs natively.

  • 2.1× decode on npanj's five-prompt benchmark, 18.9 to 39.1 tok/s on the same Mac
  • 7.4 TFLOPS prefill matmul, up from 2.4 to 3.5 through MPP
  • 4-bit weights turned into exact half values with a bit trick, products and sums stay in fp32
  • Found a split-K reduction reading through a non-coherent cache that made the fastest decode path print garbage on M1
  • Verification kernel unpacks each weight once for all parallel requests: 18 to 65 tok/s with four requests
  • 35B-A3B at 144 tok/s, and the Neural Engine prefill from upstream 1.3 works on M1/M2 too

Fork of antirez/ds4 16C · Metal · Apple Silicon, 64 GB and up

dstar: Qwen3.8-Flash-Next on a Mac

A launcher and a set of Metal kernels that run ISTA-DASLab's small quants of a 126B mixture-of-experts model (6.7B active) with the full 262K context, MTP and vision, behind an OpenAI and Anthropic compatible server.

  • 44 tok/s at 4K, 35.4 at 398K tokens of context, mostly the same code on every Apple GPU
  • Metal decoders for every quant type in the files, each checked bit-exact against the CPU
  • A 95 GiB n-gram table is never loaded: the 16 rows a token needs are read from the SSD
  • Indexer scorer rewritten for the M1: decode at 128K went from 23.8 to 33.8 tok/s, byte-identical output
  • Server keeps state at the last turn marker, so a retried agent turn on 31K tokens takes 0.3 s instead of 109 s
  • DeepSeek V4 Flash (81 GiB) streamed from the SSD on a 64 GB Mac at 12 tok/s

Local inference numbers

Everything is measured on one M1 Max with 64 GB. Decode is limited by memory bandwidth and prefill by matrix throughput, so the work is getting each close to what the chip can do without changing what the model says.

    Same math, formats the M1 has

    The M1 has no bfloat16. A 4-bit weight becomes an exact half value by putting it in the mantissa of 1024.0 and subtracting 1024. Activations widen to fp32 by appending zero bits. Every product is exact, only the order of the additions changes.

    // q is 0..15
half w = as_type<half>(ushort(q | 0x6400))
       - 1024.0h;          // exactly q
